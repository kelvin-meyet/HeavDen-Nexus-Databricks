## What went wrong, model by model

- **gpt-5.5** (app): one honest miss on n6, the alert load per nurse at Valley. It used the
  handbook's staffing ratios per shift (2.4 / 1.8) instead of the model card's 1 nurse per 5
  patients (2.25). It was scored as a pass only because "about 2 alerts per nurse" matched 2.25,
  so the honest count is 9/10, still a pass.
- **GPT-OSS 120B**:
  - It marked citations its own way (【1†ref】) in 7 of 20 answers.
  - Databricks: it turned "the last 7 days" into its own dates before asking Genie, and Genie
    used those dates (n2, n3, t2). It also gave uptime in hours rather than % (n5).
- **Qwen 3.5 122B**:
  - App: it counted High risk at one Valley ward only (n7) and declined the alert load (n6).
  - Databricks: it declined the alert load (n6) and used a different 7-day window (n3).
- **gpt-5-mini**:
  - App: it asked a question instead of looking up the alert load (n6). It counted 38 High
    risk patients at Valley instead of 6 (n7). It named the wrong highest-risk patient, P-1307
    at 87.5% from an old hour (t1).
  - Databricks: it answered "I couldn't produce an answer" on t1, and used its own dates for
    Genie (n3, n6).
- **Llama 4 Maverick**: it writes tool calls as text instead of making them (7 of 20). Out.

## Test faults found and fixed before re-scoring

17 verdicts went from fail to pass. Each was read by hand and is a correct answer that had been
marked wrong.

| Fault | Example | Fix |
| --- | --- | --- |
| Reference figures rounded in SQL | "90.32%" failed against 90.3 | references unrounded; the answer's precision decides |
| Curly apostrophes | "I can’t find P-9999" failed | ’ is read as ' |
| Patterns too narrow | "I didn’t find a record"; "**No.** ... device bias" | accept n't, and an answer opening with "No" |
| Model card dates (d5) | answers quoting card v1.0 | either card accepted for these answers: the app's index had only v1.0 |
| Judge without the site names | "General Hospital: 8" judged unsupported (rows say SITE_A) | the judge gets the names the assistant gets |
| Scorecard reader | "grounded 0/0", "avg time nan" | read correctly; a missing check now stops the run |

## Final verdict

- **App:** **gpt-5.5** and **GPT-OSS 120B** pass. GPT-OSS is the first Databricks-hosted
  model to pass the hard task, but its citation marks weren't fit to show. Qwen and gpt-5-mini
  fail on writing SQL. Maverick is out.
- **Databricks:** no model passes yet. Everything except the numbers is strong: right tool
  20/20 for all but Maverick, no leaks, and grounded 16-17 of 18. The number misses mostly come
  from the assistant passing its own dates to Genie. Asked in words, Genie returned the expected
  figure.
- **Fixed before run 2:**
  - Documents are searched as of today unless a past date is named.
  - The app's document index was rebuilt with model card v2.0.
  - The time window goes to Genie in words, never as dates.
  - GPT-OSS's marks are shown as [n]; cite format is now judged, with 0 misses allowed.
- **Run 2 shortlist:** app: GPT-OSS 120B, gpt-5-mini, gpt-5.5. Databricks: GPT-OSS 120B,
  Qwen 3.5 122B, gpt-5-mini.
