**Question:** which setup should the app's public visitors get? So, unlike runs 1 and 2, each
model ran at the setting it would ship with, not at its default:

- **gpt-5.5 at `none`**: what the app runs today;
- **GPT-OSS 120B at `low`**: what `chat/models.yaml` would ship;
- **GPT-OSS 120B at its default**: the setting that passed in run 2.

The app scorecard only (the model writes the SQL, over the demo snapshot, "now" = 3 Oct 23:00).

**Changed since run 2, all fixed before this run:**

- The app's SQL rules now say what "right now" means: the rows at `prediction_ts = now`. A stay

- Three new questions:
  - n8: which ward has the most High-risk patients right now;
  - n9: how many patients are being monitored at each site right now;

  - n6 needs a figure with a decimal, so "about 2" (the budget) no longer passes;
  - grounding is not judged on p3/p4, where the right answer denies the question's premise.

Pass marks unchanged.

**Decision rule, written before the run:** a setup counts only if it passes and shows no real
error when every answer is read. If GPT-OSS fails at both settings, the app stays on gpt-5.5.

## Every miss, read by hand

- **gpt-5.5 @ none:** one miss. On n6 (alert load at Valley) it said, honestly, that the ward data
  holds no staffing, and gave alerts per shift (25 and 35). It didn't look up the documents, which
  give 1 nurse per 5 patients. Nothing wrong, just incomplete. No accidental passes.
- **GPT-OSS @ low:**
  - **t1: it wrote the protocol's steps from memory**, without searching the documents. "Notify
    the senior nurse immediately" and "re-assess within 30 minutes" are not the protocol. It cited
    them as [1], with no passage behind the [1]. This is the most serious error in three runs: an
    invented clinical instruction with a citation that makes it look sourced. The scorecard didn't
    catch the fake [1]; reading the answers did.
  - n6: declined without using a tool.
  - t2: it averaged 8 days of uptime instead of 7 (from 26 Sep), giving 97.15 instead of 97.17.
  - d5: "5 more of 28 (≈ 18% higher recall)", without the figures. It is the card misread from
    run 2.
  - One grounded miss (n3) is the judge's fault: its own reasoning says "supported", and it
    answered no.
- **GPT-OSS @ default:**
  - n6: "about 6.75 alerts per nurse per shift". Wrong: the reference is 2.25.
  - d5: the same card misread as before, "AUROC clearly better than NEWS2's" (the card says that
    of version 1).
  - t1: the right patient and reasons, but it never named P-1735.
  - Its grounded miss (t2) is the judge's premise fault again (the answer says "not lower").
  - A slip in wording: "Northshore (General Hospital – Northshore)".

Citations: no `【…】` marks in any of the 69 answers. The only [n] without a passage is the fake
one above.

## Conclusion

- **The app stays on gpt-5.5 at `none`.** For the first time, this is measured at the setting
  visitors actually get. It passes with no real error, it is the fastest (6.3 s), and it is the
  most careful on the new questions.
- **GPT-OSS is not for the app.** By the rule fixed before the run, it fails at both settings.
- **Never ship GPT-OSS at `low`.** Thinking less, it skipped the document search and invented
  protocol steps with a citation. For the Databricks assistant, GPT-OSS stays the recommendation,
  but at its default (the setting that passed run 2). `chat/models.yaml` should drop its `low`.
- **No more re-runs of GPT-OSS on these questions.** Each fix followed by a re-run on the same
  questions makes the test easier to pass and its result worth less. The next measure of GPT-OSS
  is the Databricks run with the final instructions, which is also the first run of the new
  questions there.

## Found, not yet fixed (each helps every model)

1. **Alert load isn't defined for the app.** Genie's space defines "alerts per nurse per 12-hour
   shift" (alerts × 60 ÷ census-hours: 1 nurse per 5 patients, 12-hour shifts). The app's table
   notes don't, so every app model has guessed on n6 in all three runs. Give the app the same
   definition.
2. **The model card's "Reading it" paragraph** mixes the comparisons with version 1 and with
   NEWS2. GPT-OSS has misread it in every run.
3. **A citation with no passage behind it should fail the cite-format check.** Today only the
   read-through catches it.
